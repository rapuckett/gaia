# MVP on the simulator: the plan (milestone m0-mvp-simulator)

_2026-11-12, by the Mobile lane, which owns the milestone. Rich: "push development hard… De-prioritize security. The main focus right now is getting a mobile client MVP running on simulator and then iterating." Never committed._

**Goal:** on the iOS simulator and the Android emulator, pick a chat, send a message, watch the streamed reply, and approve a tool.

## Rules for the MVP

- **Plain HTTP to a local GAIA:** no pairing, no pinned TLS, dev builds only. The iOS simulator reaches `http://127.0.0.1:<port>`, the Android emulator `http://10.0.2.2:<port>`. The backend sees loopback, so these requests count as the PC.
- **Backend:** SRE's dev backend for repeatable work, on integration since db0d47cb0.
  - Start it with `/Users/rapuckett/Projects/gaia/.local/dev/dev-backend.sh start [--script replies.json]`; it prints `READY backend=http://127.0.0.1:42xx`, `pid=` and `home=`. Stop it with `dev-backend.sh stop <pid>`.
  - It's the real `/api`, with a scripted fake LLM and its own GAIA_HOME, in ports 4210-4229. Script entries are a string, `{"text": …}` or `{"tool_call": {...}}`; a tool call raises a real permission prompt.
  - The Android emulator reaches it through `10.0.2.2` or `adb reverse tcp:<port> tcp:<port>`. Rich's installed GAIA is a dev install and may be pointed at, after a word with Release, who owns it.
- **Types:** take them from the web UI now (`@webui/types`, i.e. `src/gaia/apps/webui/src/types/index.ts` and `api.gen.ts`). Don't wait for the Lead's schema export.
- **The app runs as a dev build (expo-dev-client)**, not Expo Go: the cached Expo Go (2.33) predates SDK 58, and a new one would be a binary download. There's one native build per platform, frugal, through the gate; JS iterates on Metro over it.
- The constants rule, the frugal-tests rule and the common brief (`subagent-brief-common.md`) all still apply. UI copy goes in webui's `i18n/locales/{en,ar}.ts`.

## App conventions (from the scaffold)

- Routes are in `src/app/` (expo-router) and thin: one feature screen each.
- Features are in `src/features/<area>/`.
- UI comes from `@/ui` only (Design's closed library); no `View`, `Text` or `StyleSheet` from react-native in features. Until a piece exists in `@/ui`, ask Design for it rather than drawing your own.
- Data comes through the hooks in `src/data/` (TanStack Query over the one `GaiaClient` in `src/api/`). Client state lives in `src/state/` (zustand). Never fetch from a feature, and never copy server data into a store.
- Copy comes through the app's `useT` (`src/i18n/`), which wraps webui's `registry.ts`. Arabic shows its English in brackets, as on the web.

## The data hooks the screens code against (A builds them, in `src/data/`)

Screens can start against these names while A lands them; A may refine the shapes and lists any change in its report.

- `useSessions()`, `useSession(id)`, `useMessages(sessionId)`, `useCreateSession()`
- `useChatStream(sessionId)`: `{ send(text), stop(), status, liveText, events, pendingPermission, pendingQuestion, error }`
- `useConfirmTool()` and `useAnswerQuestion()`, which answer the pending permission or question
- `useSystemStatus()`, which tells which model this PC runs and whether it's warming up. Read it; never a literal (the constants rule).
