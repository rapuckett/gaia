# Agent UI parity inventory: library, memory, schedules, email, mobile access, notifications, connectors, app shell, Electron shell, PC-only routes

Reference: commit 7a6e05c2f (Agent UI 0.26.0). Owner runs 0.25.0 (tag v0.25.0).
Labels are quoted from `src/gaia/apps/webui/src/i18n/locales/en.ts` (key in parentheses where it helps) or, where a string is hardcoded English in the component, from the component source (marked "hardcoded"). Electron-shell strings are quoted from the `.cjs` source.

How "Since" was decided: v0.25.0 has no i18n layer, no `pwa/`, no `manifest.json`, no `MemoryDashboardAboutYou`, no `IndexingProgress`, and none of the newer shell services (`tray-state`, `tray-host`, `keep-awake`, `window-frame`, `window-keys`, `quit-guard`, `folder-dialog`, `backend-supervisor`, the crash and renderer-gone dialogs, `engine-install`). So Since was judged per feature by reading the v0.25.0 component or service (`git archive v0.25.0`) and looking for the same control, not by key presence. A `0.25*` means the feature existed but its label or layout changed in 0.26 (the old label is noted).

Conventions: PC-only = "yes" only where the backend refuses a mobile-access request (see SEC). "n/a" for Electron-only behavior. API paths are as called by `services/*.ts` (`/api` prefix omitted by the client; written here with `/api`).

Phone-wide facts that affect many rows:
- A phone reaches the PC through an ngrok tunnel. Every `/api/*` and `/v1/*` call (except `GET /api/health`) must carry the tunnel token: `Authorization: Bearer <token>` or the `gaia_tunnel_token` cookie. The web UI gets the cookie from `https://<tunnel>/?token=<uuid>` (HttpOnly, SameSite=Strict); a native app cannot use that cookie bootstrap and must send the Bearer header. Missing or bad token returns 401 "Missing or invalid Authorization header" (`server.py` tunnel auth middleware).
- Every mutating request (non-GET/HEAD/OPTIONS) to a guarded prefix needs header `X-Gaia-UI: 1`, and an `Origin`, if sent, must be loopback, the Host or the tunnel host (`UIRequestGuardMiddleware`). A native app sends no Origin (allowed) but must send `X-Gaia-UI: 1`. A wrong Host header is a 400 "Invalid Host header: ...".
- Memory discovery/inference progress, connector events, session events and chat streams use `EventSource` (SSE). React Native has no built-in EventSource; it needs a polyfill that can set the Bearer header.
- The web app already has a mobile layout (`max-width: 768px`): sidebar becomes an overlay, the Mobile access button is hidden, and each chat row gets a single "⋯" menu.

## SEC: routes the backend refuses over mobile access

A request counts as "over mobile access" when `request.client.host` is not loopback **or** any of `x-forwarded-for`, `x-forwarded-host`, `x-forwarded-proto` is present (ngrok adds them) (`security.py`: `require_local_pc`, `via_tunnel`; `logs.py` has its own copy `_at_this_pc` with a different message; `lemonade.py` and `providers.py` call `via_tunnel` inline). - Not refused but PC-acting: `POST /api/files/open` (opens a file or reveals it in Explorer/Finder on the PC), `POST /api/system/unload-model`, `POST /api/system/load-model`, `POST /api/tunnel/start|stop` (a paired phone can stop the tunnel that serves it).
- A refused call returns FastAPI `{"detail": "<message>"}` with 403; the web UI shows the detail text.
- SEC-A1 (autonomous runs while the tunnel is up): when `app.state.tunnel.active` is true and env `GAIA_AUTONOMOUS_ALLOW_TUNNEL` is not `1`, `true` or `yes`, the scheduler's executor raises `RuntimeError("Scheduled run suspended: public tunnel is active. Stop the tunnel or set GAIA_AUTONOMOUS_ALLOW_TUNNEL=1.")` (`server.py` `_schedule_executor`). A timed run therefore fails with that message, shows on the schedule card ("Last run failed: ..."), and raises an Errors notification. "Run now" goes through the same executor (`scheduler._execute_task` calls `self._executor`), so it fails the same way. Present in v0.25.0.
- SEC-A2: the autonomous agent loop (`agent_loop.py`, approved goals and agent-inferred work) ticks `LoopDirective("idle")` with a debug log only while the tunnel is active and the env var is not set; there is no user-visible message. Present in v0.25.0. Consequence for a phone user: schedules and goals stop working exactly while their phone is connected unless the PC owner sets the env var; the UI does not warn before the tunnel starts (undetermined whether a warning exists in the Settings text; no label found).
