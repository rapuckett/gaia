# Chat surfaces: parity inventory (Agent UI 0.26.0, commit 7a6e05c2f)

Scope: 64 files under `src/gaia/apps/webui/src/components/` plus the guide sections named in the brief.

How to read this file

- Labels are quoted from `src/gaia/apps/webui/src/i18n/locales/en.ts` unless a row says "hard-coded". Many chat strings are still hard-coded English in the components (they are not in en.ts); those are quoted from the component and flagged. `{x}` is a template placeholder. `.one`/`.other` are plural pairs.
- **Since:** `en.ts` and `useT` do not exist at v0.25.0 (every string was hard-coded then), so Since was decided by whether the feature's code or English text exists in the v0.25.0 tree, not by key. A component file that is new in 0.26 may still hold a 0.25 feature that was moved (noted where so).
- **PC-only:** only one chat-scope call is refused over mobile access: `PUT /api/chat/permissions` (the default mode for new chats; `require_local_pc`, `src/gaia/ui/routers/chat.py`). Refusal text (403): "Change this on the PC running GAIA. It can't be changed over mobile access or from another computer." It is called from Settings > Permissions, outside this file list; it is listed as PRM-24 so the pairing is not lost. Two more PC-only refusals sit next to chat surfaces: the model-server log read behind the "Model server log" button (CV-31, 403: "Read GAIA's logs on the PC running GAIA, not over mobile access or from another computer.") and provider-key entry (CMP-26, 403: "Enter provider keys on the PC running GAIA, not over mobile access."). Nothing else in these 64 files is refused over the tunnel. But many actions "succeed" and act on the PC (open a file, show in folder, browse the PC's folders); those are called out in Notes, with PC-only left as No.
- Per-chat calls (`PUT /api/chat/permissions/{id}`, `POST /api/sessions/{id}/environment/...`, `POST /api/tunnel/start`) are not refused over mobile access.
- API prefix: every path is under `/api`. Streaming chat is SSE (`POST /api/chat/send`, `GET /api/chat/attach`).
- Keyboard-only affordances are listed because a phone needs a touch substitute. Where the web UI is hover-only, Notes says so.

Shared global shortcuts used by these surfaces (defined in App, outside this list): `Ctrl+K` (focus chat search), `Ctrl+Shift+O` (new chat), `Ctrl+B` (sidebar), `Ctrl+,` (Settings). On macOS the app labels them with the Command key.

## Open questions

1. **Message-actions hover on a phone.** The web UI relies on hover (`.msg:hover .msg-actions`) for every message except the latest answer. The native app needs a decision (long-press sheet versus an always-visible row). The matrix should treat CV-16 to CV-23 as one "message actions" feature with a touch alternative.
2. **Session-panel Files polling.** The guide says the panel "never checks on a timer", but `SideRail.tsx` re-checks file status every 4 s (`FILE_RECHECK_MS`) while the section is visible. I treated the code as authoritative; the guide may be stale (not edited, as this task is read-only).
3. **Open / Show in folder from a phone.** The backend does not refuse `POST /api/files/open` over the tunnel; it launches Explorer or Finder on the PC. I marked these rows PC-only = No and described the behavior in Notes. If the parity matrix wants "PC-only" to include "acts on the PC with no effect on the phone", CV-26, CV-46, SP-06 and SP-24 are the rows to flip.
4. **Log button over the tunnel.** Resolved: the refusal text is quoted in CV-31. Left open: whether the web UI hides or shows the 403 when a phone taps the button (the component shows it for any local-model failure, so a phone user would see the error).
5. **"Since" for restructured features.** `en.ts` does not exist at v0.25.0 (strings were inline), so Since follows the code. Where a 0.25 feature was rebuilt (the answer stats line CV-38, the agent activity block CV-41, the model menu CMP-23, the permission prompt PRM-05 and PRM-09) I marked the feature 0.25 or 0.26 per the rows' Notes; a stricter reading could split them.
6. **Strings not in en.ts.** Hard-coded English remains in TurnChanges, ChangesReview, ChangesSection (Commit / PR dialogs and result messages), QueuedMessages, SessionDocsBar, PrivateChatButton, ChatView (a number of titles), GuideCard notices and the calculator labels, ConfirmationCard, UnsupportedCard and CardErrorBoundary, the ModelChip download-error messages and RetryWithMenu empty states. A phone app measured against the web UI's localization will need these keys added (or left English).
7. **Server-supplied text.** The "older messages out of view" note (CV-52), library notices (CV-53), the guide's "75 minutes without progress" reply (CV-40), start-screen card titles (NC-14), the model's place labels and cloud privacy notice (CMP-22, CMP-24) arrive as English from the server; I could not determine whether the Arabic build translates them (some are rebuilt from the English via `cardLine`).
8. **EmailPreScanCard and ConnectorRetryBanner / ModelServerDownNotice / TroubleshootingReport / ResourceMonitor / DownloadChip / ModelStatusPill** are mounted by the chat surfaces but sit outside this file list; I gave each a pointer row (CV-02, CV-13, CV-14, CV-31, SB-25, SB-26, RC-20) and did not inventory them.
