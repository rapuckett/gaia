# Agent UI parity inventory: settings, first-run setup, system status

Reference: commit 7a6e05c2f (Agent UI 0.26.0). Owner runs 0.25.0 (tag v0.25.0).
Source: `src/gaia/apps/webui/src/components/`. Labels are quoted from `src/gaia/apps/webui/src/i18n/locales/en.ts` (English and Arabic only; `ar.ts` is the second locale).

## How to read this file

- **Since**: `0.25` if the feature exists at v0.25.0, `0.26` if added after. The i18n catalog (`en.ts`) did not exist at v0.25.0, so Since was decided from the v0.25.0 component source (hard-coded English labels) and its API calls. Where a feature existed at 0.25 under another label or place, Notes say so.
- **PC-only** is `Yes (Rn)` when the backend refuses the call over mobile access (the ngrok tunnel, `X-Forwarded-*` headers) or from another computer. The refusal codes are quoted once here:

| Code | Refusal text the user sees (HTTP 403) | Calls refused | Source |
|---|---|---|---|
| R1 | "Change this on the PC running GAIA. It can't be changed over mobile access or from another computer." | `PUT /api/settings` when the body sets `network_policy`; `PUT /api/chat/permissions` (default mode); every `/api/messaging/*` call; `POST /api/gpu-memory/apply`; `POST /api/gpu-memory/revert`; `POST /api/setup/npu/memlock-fix` | `require_local_pc` in `security.py` |
| R2 | "Enter provider keys on the PC running GAIA, not over mobile access." | `POST /api/providers/{id}/connect` when the body carries an API key (connecting with an already saved key is allowed) | `via_tunnel` in `routers/providers.py` |
| R3 | "Change the model server on the PC running GAIA, not over mobile access." | `POST /api/lemonade/target` | `via_tunnel` in `routers/lemonade.py` |
| R4 | "Read GAIA's logs on the PC running GAIA, not over mobile access or from another computer." | `GET /api/logs`, `GET /api/logs/{source}` | `_at_this_pc` in `routers/logs.py` |

- The web UI does not hide or grey out PC-only controls over the tunnel. The call fails and the component shows the refusal text inline (`settings-error` or `ErrorNotice`). A phone app should either hide those controls or show the refusal text.
- **Desktop shell only** means the control needs an Electron bridge: `window.gaiaAPI` (tray, taskbar flash, keep-awake), `window.gaiaUpdater` (updates), `window.gaiaInstall` (install screen). A phone has no equivalent, so these rows are "n/a on phone" unless the phone app chooses a substitute. No `window.gaiaDesktop` bridge exists in this commit.
- API paths are written with the `/api` prefix. Client functions live in `services/api.ts`, `setupApi.ts`, `memoryApi.ts`, `messagingApi.ts`, `speechApi.ts`, `chatTurnApi.ts`.
- Settings sections, in the order `SettingsDialog` shows them (`SECTIONS`): General, Setup, Model, Permissions, Skills, Connectors, Messaging, Memory, Notifications, Read aloud, Privacy, Advanced. That is 12. v0.25.0 had 8 (General, Model, Permissions, Skills, Connectors, Memory, Privacy, Advanced). Setup, Messaging, Notifications and Read aloud are 0.26.

Section ID codes: SET-NAV (dialog chrome), SET-GEN, SET-SETUP, SET-MODEL, SET-PERM, SET-SKILL, SET-CONN, SET-MSG, SET-MEM, SET-NOTIF, SET-VOICE, SET-PRIV, SET-ADV. FR = first-run setup and engine install screen. MS = model status, server, resources, logs, troubleshooting, updates, notices, error boundary.

## First-run setup and engine install (FR)

First-run setup is `SetupScreen` (also reopened from Settings → Setup → "Run setup again" and from "Set up local models"). Its steps in the rail are "Check this PC", "Your setup", "Download", "Test", "Ready"; "Customize" adds sub-screens (GPU memory, models, cloud key). At 0.25 it was a single screen: choose where GAIA runs (On this PC, Fireworks AI, AMD LLM Gateway), enter a key, optionally pick an existing Lemonade, then a progress view. Everything else below is 0.26 unless marked.

Re-run mode shows "Back to GAIA" and Settings is closed first. The `POST /api/setup/run`, `/api/setup/models/*`, `/api/setup/cancel` and status calls are not refused over the tunnel by the backend, but the work (install, downloads, model tests) runs on the PC. Only the GPU memory change and the NPU memlock fix are PC-only (R1).

## Open questions

1. **`ConnectorsSection` is not in this file list.** `ConnectorsPane.tsx` only wraps it. Its controls (Google, Microsoft, GitHub OAuth, MCP-server connectors, per-agent grants) need rows from whoever owns it. The server also treats `/v1/connections` as sensitive over the tunnel (`server.py` gate), but I did not find a per-call `require_local_pc` on the connector routers in `src/gaia/ui/`; that was not checked in depth because the routers live outside the stated scope.
2. **Shortcut list at 0.25 (SET-GEN-20).** The 0.25 source has Send, New line, Stop, New chat, Search chats, Show or hide the sidebar and Settings by label; the exact key chords at 0.25 were not compared.
3. **0.25 label evidence is by source search, not by a running 0.25 app.** Since values for features that existed at 0.25 under different wording (for example update controls in Advanced, the Device select in Model, `Context size in tokens` in Advanced) come from reading `git show v0.25.0:` sources. Where a 0.25 label differs, Notes say so.
4. **Platforms for GPU memory.** `gpu_memory.status()` returns `applies: false` and hides the step on non-AMD-iGPU machines, but I did not confirm whether macOS or Windows-on-Intel are both hidden by `_hidden` or only by the AMD check. For a phone this affects only what the PC reports.
5. **Resource strip and the memory dashboard are PC data.** I could not confirm whether `/api/system/resources` is reachable over the tunnel with the tunnel token (it is not gated by `require_local_pc`), so it may work from a phone, but nothing in the web UI is mobile-aware.
6. **Settings values stored on the device versus the PC.** Appearance, colors, language, resource-strip visibility and all Notifications settings are client-side (`chatStore`, `resourceMonitorStore`, `notificationStore`), so a phone would hold its own copy; nothing syncs them. The guide says language is "remembered by this device".
7. **The guide's Models table row for Local says "pick CPU, GPU or NPU for new chats".** The Device control that did this was removed in 0.26 (no row exists). The guide is stale on that point.
8. **Phone reachability of first-run setup.** The setup calls are not refused over the tunnel, but the UI gate (`/api/setup/check`) normally runs before a phone could pair. Nothing in the code says a phone may run setup; treat FR as PC-first unless Rich decides otherwise.
